# 块外镜像覆盖（2026-11-23，任务 7.5）

## 背景

`deploy/helm/ontoaxis-jobs/values.yaml` 的 `backup.image` 位于 `components:` 块之外。
旧版 `extract_helm` 只解析 `components:` 下的组件，这条引用因此不进 lock、不进审计，
也不受 `E_LATEST` / `E_NODIGEST` 约束，只被例外 `helm-placeholder-digests` 的 scope
间接覆盖——回填 6.1 时会被漏掉，例外到期也不会因它报错。

## 修正

- `extract_helm` 改为解析 values 中所有 `image:` 映射：
  - `components:` 内的映射仍按组件块名归属（行为不变）；
  - `components:` 外的映射（如 `backup.image`）不归属组件，由 `component_key` 按镜像名
    回退，本例回退为 `postgres`，无需新增 policy 条目；
  - 镜像映射遇到同级或更浅的键即结束，组件层的 `tag` 不会被误当 `image.tag`。
- 锁文件新增 1 条（45 → 46），其余 45 条逐字节不变。

## 验证输出

```
$ git diff deploy/deps/lock.yaml
@@ -210,6 +210,12 @@ entries:
+  - source: deploy/helm/ontoaxis-jobs/values.yaml
+    line: 25
+    component: postgres
+    image: docker.io/library/postgres
+    tag: ""
+    digest: "sha256:6fea524445be83b661e89d8c10d4280535e3ec8af116d4f0a9395d28adf67872"
```

`line: 25` 即 `repository:` 所在行；`component: postgres` 是按镜像名回退的结果。

## 影响

- 任务 6.1 的回填范围由「21 个组件」修正为「22 条镜像引用（21 个组件 + jobs 备份镜像）」；
- 例外 `helm-placeholder-digests` 的覆盖范围现在与审计可见范围一致（22 条）；
- 未修改 `deploy/helm/` 任何 values 内容，仅改变抽取覆盖范围。
