# 信息架构 — OntoAxis 核心工作台

> 状态：draft（2026-11-25）
> 上游：[brief.md](brief.md)
> 本文描述目标 IA 与迁移路径；“现状”与“提案”分列，未实现的能力不写成事实。

## 1. 结论

当前是 6 个平级 CRUD 页面，用户必须在脑内维护“对象类型—属性—关系—实例—数据集—查询”的关系。目标 IA 把**对象类型变成导航脊柱**：

```text
项目
└── Ontology
    └── 对象类型（hub）
        ├── 属性
        ├── 关系类型
        ├── 数据集        ← 契约就绪后启用
        ├── 实例
        └── 查询          ← 契约就绪后启用
```

其他页面（数据集、对象浏览、查询、审批）保留，但它们要么从 hub 进入，要么带着上下文返回 hub。

## 2. 现状审计

| 路由 | 当前职责（文件） | 主要问题 |
| --- | --- | --- |
| `/projects` | 项目列表与创建（[ProjectsPage.tsx](../../web/src/features/projects/ProjectsPage.tsx)） | 项目不约束任何内容；没有项目切换器；创建后无去处 |
| `/ontology` | 对象类型与关系类型，主从布局（[OntologyPage.tsx](../../web/src/features/ontology/OntologyPage.tsx)） | 只有属性和关系；不能进入实例、数据集或查询；选中项不在 URL |
| `/object-explorer` | 类型下拉 + 实例表 + 右侧详情（[ObjectExplorerPage.tsx](../../web/src/features/object-explorer/ObjectExplorerPage.tsx)） | 类型上下文弱；UUID 折行占据首列；整行 `onClick` 不可键盘操作；详情不可深链 |
| `/datasets` | 列表、创建、预览模态（[DatasetsPage.tsx](../../web/src/features/datasets/DatasetsPage.tsx)） | 没有详情路由；预览后无处可去；绑定接口已在后端，前端未接入、无互链 |
| `/queries` | 保存查询 + SQL 编辑器 + 结果（[QueriesPage.tsx](../../web/src/features/queries/QueriesPage.tsx)） | 没有数据集/类型上下文；保存查询不可深链；结果与错误状态混在页面内 |
| `/approvals` | 待审批队列 + 详情模态（[ApprovalsPage.tsx](../../web/src/features/approvals/ApprovalsPage.tsx)） | 模态不可深链；与执行详情未互链；截止时间缺少紧迫度表达 |
| `/login` | 左右分栏品牌页（[LoginPage.tsx](../../web/src/features/auth/LoginPage.tsx)） | 对内部工具过重；功能描述使用内部术语（Resource-first） |

跨页面问题：

- 顶栏标题与页头标题重复（如“Ontology 管理”出现两次）。
- 每页都有一枚“Stage 1 · 核心工作台”eyebrow；它描述项目阶段，对用户任务无信息量。
- 导航是 6 个平铺项；没有分组，也没有“当前项目”。
- 主实体（对象类型、对象实例、数据集、审批）没有可收藏、可分享的详情 URL。
- 空态、错误态、无权限态没有统一契约；降级（如搜索不可用）没有专门表达。

## 3. 目标壳层

```text
┌ 项目：客户 360 ▾ ────────────────────────────────────────────────┐
│ 建模  数据  分析  治理                          语言  用户 ▾      │
├──────────┬──────────────────────────────────────────┬────────────┤
│ 对象类型  │ 项目 / Ontology / Customer                │ 检查器      │
│ 关系类型  │ Customer  customer                        │ tier        │
│          │ 客户主数据                                 │ string      │
│          │ 4 个关系　1 个数据集                       │ 必填        │
│          │ [概览][属性][关系][数据集][实例][查询]      │ 唯一        │
│          │ ──────────────────────────────────────── │             │
│          │ 属性表（13px，40px 行高，标识符等宽）       │             │
└──────────┴──────────────────────────────────────────┴────────────┘
```

- **项目切换器**位于左上，承载“当前项目”并持久化；项目设置从切换器进入。
- **导航分组**：建模 / 数据 / 分析 / 治理。只放已存在或已批准的能力；规划项不进入 v1 导航，不做禁用死链。
- **顶栏**只保留项目、面包屑、语言、用户；页面标题交给页头，避免重复。
- **检查器**承载次级选择（属性、关系、实例预览），宽度 360px；不把每次选择都变成新页面。
- **主轴轨**：左侧导航右缘一条 1px 轴线，分组标签带刻度；这是唯一的结构装饰，编码层级而非装饰。

## 4. 对象类型 hub

对象类型是唯一同时连接 schema、实例和数据的实体，因此作为 hub。

| Tab | 内容 | 数据来源 | 状态 |
| --- | --- | --- | --- |
| 概览 | 标识、描述、主键、属性数、关系数、更新时间 | 现有 `object-types` / `link-types` | 现在可做 |
| 属性 | 属性表 + 检查器 + 新建属性 | 现有 `properties` | 现在可做 |
| 关系 | 以该类型为 source/target 的关系类型 | 现有 `link-types` 过滤 | 现在可做 |
| 实例 | 该类型的对象实例列表 | 现有 `objects` + `object_type_id` 过滤 | 现在可做 |
| 数据集 | 该类型绑定的单个 backing dataset | 现有 `dataset-binding` 接口与 `backing_dataset_id` | 可做（P2）；前端尚未接入 |
| 查询 | 引用该类型的保存查询 | saved query 无类型关联字段 | 暂不实现；不显示空壳入口 |

交互约定：

- 每个 tab 是可分享 URL；浏览器前进/后退可用。
- 新建/编辑用模态；查看主实体用路由。模态只用于短表单和确认，不承载主详情。
- 选中属性或关系时更新右侧检查器，不改变 URL；需要分享时提供“打开详情”链接。
- 面包屑：`项目 / Ontology / <类型显示名>`；标识符在标题下方以等宽字体显示。
- 主操作只有一个：`新建属性`（属性 tab）或 `编辑类型`（概览）；次操作降级为文本按钮。

## 5. 路由契约

| 现状 | 提案 | 说明 |
| --- | --- | --- |
| `/` → `/projects` | 保留 | 无当前项目时进入项目选择 |
| `/projects` | 保留 | 项目列表；有当前项目时作为“所有项目”入口 |
| — | `/projects/:projectId/settings` | 规划；项目级设置 |
| `/ontology` | 保留 | 对象类型列表，默认进入第一个类型的概览 |
| — | `/ontology/object-types/:objectTypeId/:tab?` | hub；`tab` ∈ `overview/properties/links/datasets/instances/queries` |
| — | `/ontology/link-types/:linkTypeId` | 关系类型详情；P2 |
| `/object-explorer` | `/objects?type=:objectTypeId` | 列表保留查询参数；旧路径做重定向 |
| — | `/objects/:objectId` | 实例详情；可直接打开 |
| `/datasets` | 保留 | 列表 |
| — | `/datasets/:datasetId` | 详情：schema、预览、绑定（规划） |
| `/queries` | 保留 | 工作台 |
| — | `/queries/:queryId` | 打开已保存查询 |
| `/approvals` | 保留 | 队列 |
| — | `/approvals/:approvalId` | 详情路由；模态改为路由或可深链抽屉 |
| `/login`、`/auth/callback` | 保留 | 简化视觉，不改流程 |
| — | `/design` | 仅开发环境；组件与状态目录，不进入生产导航 |

Refine resource 与路由的映射保持一一对应；嵌套资源（properties）通过父资源路径构造，不新增顶层导航。

## 6. 关键流程

### J1 建模

```text
项目 → Ontology → 新建对象类型（模态）
     → 属性 tab → 新建属性（模态）→ 检查器确认
     → 关系 tab → 新建关系（模态，选 source/target）
     → 概览：属性数、关系数、影响面（契约就绪后）
```

失败路径：名称冲突、必填缺失、无权限、后端 5xx。每种都在表单内就地显示，不关闭模态、不丢输入。

### J2 探索

```text
对象类型 → 实例 tab → 筛选（属性值 / 关键词）
        → 选中行 → 检查器（属性、版本、关系）
        → 打开详情路由 → 复制 ID / 查看原始 JSON
```

要求：UUID 在表格中单行显示，超出用省略 + 复制；不允许折成两行。

### J3 查询

```text
数据集详情 → schema 预览 → “查询此数据集”
          → 查询页携带数据集上下文 → 执行 / 解释 → 保存
```

要求：上下文条始终可见；执行失败显示错误码与 `request_id`；结果为空与查询失败必须区分。

### J4 审批

```text
审批队列 → 详情 → 查看执行上下文与截止时间 → 批准/拒绝 + 备注 → 队列就地更新
```

要求：决定后不回到空白页；乐观更新失败时回滚并提示。

## 8. 状态契约

所有列表与详情页必须实现以下状态；不允许用空态代替错误或无权限。

| 状态 | 列表 | 详情 | 规则 |
| --- | --- | --- | --- |
| 加载 | 5–8 行骨架，保留表头与筛选 | 标题 + 骨架块 | 不用整页 spinner；短操作才用按钮内 loading |
| 空（无数据） | 一句话说明 + 主操作 | 说明 + 返回/创建 | 区分“还没有”与“没搜到” |
| 空（无匹配） | 保留筛选，提示清除条件 | — | 不显示“创建”诱导 |
| 错误 | 错误码 + `request_id` + 重试 | 同上 | 不暴露堆栈；不吞异常 |
| 无权限（403） | 面板级提示，不渲染数据 | 路由级 403 页 | 绝不复用空态 |
| 降级 | 顶部横幅说明哪个能力不可用 | 局部禁用 | 例如搜索不可用时禁用搜索，不返回静默空结果 |
| Mock | 持久徽标 | 同左 | 不得让合成数据看起来像生产数据 |
| 部分字段 | `—` + “未返回” | 同左 | 不臆造默认值 |
| 陈旧 | 显示最后更新时间 + 刷新 | 同左 | 超过阈值时标注“可能已过期” |

数据极限也要设计：200 个属性、超长中英文名、UUID、空属性对象、单值超长文本、0 条结果、1000+ 实例、慢查询（>10s）。

## 9. 响应式、键盘与可访问性

- **断点**：≥1280 三栏；1080–1279 检查器改为抽屉；720–1079 导航轨收为 64px 图标 + tooltip；<720 不作为目标，但表格横向滚动、不得溢出。
- **键盘**：提供跳转到主内容的 skip link；导航使用真实链接；tab 使用 roving tabindex + 左右箭头；模态焦点陷阱、Esc 关闭、关闭后焦点回到触发元素。
- **表格行选择**：主单元格用链接或按钮，禁止只给 `<tr>` 绑 `onClick`（现状问题）。
- **焦点**：统一 `:focus-visible`，2px 实线 + 2px offset；不得用 `outline: none` 裸奔。
- **颜色**：状态与数据类型不得仅靠颜色区分，必须带文字或形状。
- **动效**：尊重 `prefers-reduced-motion`；动效只用于状态反馈。
- **文案**：中文不使用全大写与字距；英文句首大写；标识符不翻译；错误文案说明发生了什么、如何继续。

## 10. 迁移顺序

1. 壳层 + 项目上下文 + 设计目录（不改变业务页面）。
2. 对象类型 hub（旗舰页），覆盖全部状态。
3. 对象浏览改造，验证“类型 → 实例”链路。
4. 数据集详情与查询工作台，验证“数据 → 查询”链路。
5. 审批详情路由与登录页简化。
6. 其余规划能力在契约就绪后加入；不得提前做成空壳入口。
