# 界面设计 brief — OntoAxis 核心工作台

> 状态：draft（2026-11-25）
> 负责人：klb3713（待确认）
> 关联：[information-architecture.md](information-architecture.md)、[tokens.md](tokens.md)

## 1. 一句话

OntoAxis 把分散的数据集变成有类型、有关系、可探索、可查询的对象模型。核心工作台的界面任务，是让建模者、数据工程师和分析师**在同一条模型链路上移动**，而不是在六个互不相通的列表之间切换。

## 2. 当前能力与边界

已经存在（`web/src/features/`）：

- 项目列表与创建；
- 对象类型、属性、关系类型的查看与创建；
- 对象实例按类型浏览与单条检查；
- 数据集列表、创建与预览；
- 保存查询、SQL 执行与执行计划；
- Action 人工审批（列表、详情、批准/拒绝）；
- mock 与真实 `/api/v1` 双模式、OIDC 登录、中英双语。

当前不在界面范围（不得在设计中当成已实现）：

- Pipeline 编排与运行详情；
- 连接器 / 数据源配置；
- 权限策略与审计查询；
- Ontology 图视图、对象关系图；
- 数据集与对象类型的绑定可以在后端完成（`POST/DELETE /api/v1/ontology/object-types/{id}/dataset-binding`，对象类型 DTO 含 `backing_dataset_id`），但前端尚未接入，不能当成已有界面能力。

## 3. 用户（假设，待验证）

目前没有用户研究记录。以下是基于页面清单、领域模型和架构文档的假设，必须用 3–5 位真实用户验证后再定稿。

| 角色 | 目标 | 现有摩擦 | 成功信号 |
| --- | --- | --- | --- |
| 数据建模者 | 定义并演进对象类型、属性、关系 | 看不到类型被哪些数据集/查询使用；属性和关系分散在两个 tab | 改动能回答“影响谁”，并在一个页面完成 |
| 数据工程师 | 把数据集接入模型，保证 schema 与新鲜度 | 数据集页与对象类型页没有互链；预览后无处可去 | 从数据集能看到它服务哪些类型，反之亦然 |
| 分析师 / 业务 | 找到对象实例并查询 | 对象浏览以 UUID 为首列，类型上下文弱；查询页没有数据集上下文 | 3 次点击内从类型到一条记录 |
| 平台管理员 | 处理审批、识别降级与权限问题 | 审批与执行详情未互链；403 与空态未区分 | 待办清楚，异常状态可解释 |

使用环境假设：企业内网、桌面 1280–1600、长时间连续使用、中英文标识符混排、键盘操作比例高于消费级产品。

## 4. 三个核心任务

### J1 建模：定义并演进一个对象类型

起点：当前项目 → Ontology。  
终点：一个对象类型具备属性与关系，并能看到它被谁使用。  
成功标准：新用户在 5 分钟内完成“3 个属性 + 1 个关系”，且能看到该类型绑定的数据源（当前模型为单个 backing dataset）。  
备注：保存查询与对象类型暂无关联字段，“被哪些查询引用”不纳入本阶段承诺；缺失时显示“暂不可用”，不得用估算数字冒充。

### J2 探索：从类型到一条实例

起点：对象类型。  
终点：一条对象记录的属性、版本、关系与来源。  
成功标准：从类型到记录不超过 3 次点击；UUID 不折行；详情可从 URL 直接打开。

### J3 查询：带着上下文写 SQL

起点：数据集或对象类型。  
终点：执行结果、执行计划，或保存为查询。  
成功标准：编辑 SQL 时上下文（数据集、schema）始终可见；失败时显示错误码与 `request_id`，不是一句“出错了”。

### J4 审批（支撑任务）

起点：待审批队列或某次 Action 执行。  
终点：批准/拒绝并留下备注。  
成功标准：截止时间、执行上下文、决定结果在同一个视图内；操作后状态不回退。

## 5. 设计原则

1. **模型是导航单位**：对象类型是 hub，不是六个平级列表之一。
2. **标识符是一等内容**：`customer_id`、UUID、版本号用等宽字体和正确的换行规则，不用装饰性胶囊包起来。
3. **密度是尊重**：面向长时间看表的用户；行高、列宽、对齐优先于留白美感。
4. **状态即界面**：加载、空、错误、无权限、降级、mock、字段缺失都是设计对象，不是兜底。
5. **一个信号色**：强调色只用于当前路径与可执行动作；类型和状态用各自的功能色，且不得只靠颜色表达。
6. **不伪造**：mock、降级、部分字段缺失必须显式标注；空结果与无权限必须区分。

## 6. 非目标

- 不是通用 BI 或报表搭建器；
- 不是 Pipeline / 流程设计器；
- 不是低代码应用搭建器；
- 不以移动端或暗色模式为首要场景；
- 不是品牌站或营销页；登录页也应服务于内部工具的效率。

## 7. 约束

- 技术栈：React 19 + Refine + TypeScript + Vite，CSS-first；新增运行时依赖需先说明用途与替代方案。
- 组件策略：优先保留现有 CSS 体系；行为型组件（Dialog/Select/Tabs/Menu/Tooltip）可引入 Radix，是否引入 Tailwind/shadcn 需单独决策。
- 可访问性目标：WCAG 2.2 AA（对比度、键盘、焦点可见、错误可识别）；不以“内部工具”为由豁免。
- 国际化：中英双语等长支持；中文不使用全大写与字距；英文标识符保持原样。
- 安全：前端不假设权限；403 必须显示为无权限，不得退化为空列表。
- 性能：Web 字体需自托管、子集化并 `font-display: swap`；首屏不依赖字体加载完成。

## 8. 成功标准

- **5 秒测试**：新用户看到任一页面，能说出“当前项目、当前对象类型、下一步能做什么”。
- **任务测试**：3–5 位目标用户完成 J1–J3，无关键性错误；记录完成时间与卡点。
- **状态覆盖**：所有列表/详情页实现 IA 中的 8 类状态。
- **系统一致性**：功能样式中不出现裸 hex；所有可交互元素有 `:focus-visible`。
- **证据**：每个改造页面提供前后截图与 Playwright 视觉快照；不得用“看起来更好”代替验证。
- **不回归**：现有 `pnpm check/build/test` 与 Playwright E2E 保持绿色。

## 9. 待确认问题

| # | 问题 | 影响 | 建议 |
| --- | --- | --- | --- |
| Q1 | 项目是否进入 URL（`/projects/:id/...`） | 深链接、多项目、权限 | 建议进入；若暂不做，需定义“当前项目”的持久化与切项目行为 |
| Q2 | Web 字体预算与内网可用性 | 视觉方向、首屏 | 先自托管 IBM Plex 子集；不可行则退回系统字体并保留比例尺 |
| Q3 | 是否需要暗色模式，何时 | token 结构 | v1 不做；语义层保留重映射 |
| Q4 | 图视图优先级 | 对象类型 hub 的形态 | 先做表 + 检查器；图作为独立 tab 后续加入 |
| Q5 | 平板/小屏支持到什么程度 | 响应式断点 | 桌面优先；1080 以下折叠检查器，720 以下保证不溢出 |
| Q6 | 无权限时隐藏还是禁用入口 | 安全与可用性 | 入口可隐藏，直达 URL 必须显示 403 状态；两者都不得暗示可访问 |
| Q7 | 单个 backing dataset 是否满足建模需求 | 数据集 tab 的形态 | 先按单数据集设计；多数据集映射需后端契约扩展 |
